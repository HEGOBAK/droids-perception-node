# M7 — Geometry and a 3D viewer

[Start here](../START_HERE.md) · [Previous: M6](M6.md) · [Next: M8](M8.md)

**Goal:** turn valid synchronized measurements into points in a defined coordinate system.

## Define the geometry first

Use a right-handed world frame: x forward, y left, z up at startup. Define base, servo and range frames on a drawing. Keep the base origin fixed for the initial experiment. Mount the IMU rigidly to the base, and the range sensor with the camera on the rotating assembly; record offsets and orientation. If mounting differs, change the transform chain.

For a range beam whose local forward axis is +x, `p_R=[d,0,0]`. With homogeneous transforms, `p_W = T_WB * T_BS(theta) * T_SR * [d,0,0,1]`. Each T is 4×4; the point is 4×1. `T_BS` includes the servo pivot offset, axis and rotation. `T_SR` is the fixed sensor-to-servo mounting transform. Set base translation constant only because the experimental origin is fixed.

For one common convention, `R_WB = Rz(yaw) Ry(pitch) Rx(roll)`. This multiplication order acts right-to-left on column vectors. Implement it consistently; angles are radians. If firmware uses a different convention, convert explicitly.

## Assignment

1. Implement geometry in a pure Python module before live plotting. Test identity, positive 90° yaw, known translation, and inverse round-trip. For zero offsets and neutral servo, d=1 gives `(1,0,0)`; +90° yaw gives `(0,1,0)` under the convention above.
2. Add actual servo-axis geometry and measured offsets. Verify rotation matrices are orthonormal and preserve vector length. Test signs using physical movements.
3. Plot synthetic data labeled **synthetic**. Then replay recorded valid packets before attempting live updates.
4. Add a bounded trajectory history with labeled meter axes, validity/freshness status, and reset behavior. Do not redraw an unlimited history each frame or block serial parsing on GUI rendering.
5. Align timestamps and reject excessive skew. Compare points for a fixed target while slowly rotating the base within the valid experiment.
6. Explain association: the ultrasonic beam measures a reflecting surface, not a selected image pixel. Only plot a colored-target position when alignment and scene design justify that assumption; otherwise label the point as a range return.

If using camera rays, calibrate intrinsics and use `[ (u-cx)/fx, (v-cy)/fy, 1 ]` in the conventional camera frame, then transform axes explicitly. Applying ultrasonic range along this ray requires justified co-registration and association; it is not automatically correct.

## Finish when

- Synthetic geometry tests pass and measured points have units and defined frames.
- Reset, invalid data and stale samples do not silently extend the trajectory.
- The report states fixed-origin, heading-drift, beam-association and servo-angle limitations.

## Explain

Why does transformation order matter? Why cannot orientation plus one distance reveal an arbitrary moving sensor's world position? Why is this a constrained mapping demonstration rather than full SLAM?

**Evidence:** transform drawing, tests, labeled plot and an actual fixed-target experiment.
