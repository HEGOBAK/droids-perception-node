# M6 — Binary UART and robust parsing

[Start here](../START_HERE.md) · [Previous: M5](M5.md) · [Next: M7](M7.md)

**Goal:** transport measurements reliably without blocking control.

Use [PROTOCOL.md](../docs/PROTOCOL.md) as the proposed byte-level contract. Read the [UART guide](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/uart.html) and confirm that your selected physical connection actually carries UART. Native USB and UART are different interfaces.

## Assignment

1. Create a pure Python encoder/decoder in `host/protocol.py` and unit tests before connecting serial hardware. Use `struct` with explicit little-endian format, bounded buffering and the named CRC variant.
2. Make a golden packet using known values and independently verify field offsets, length and CRC. Implement the same serialization in C and compare exact bytes. A raw `sizeof(struct)` dump is not a portable wire format.
3. Run all corruption/chunking cases listed in the protocol document. Use `python -m unittest discover -s tests -v` once tests exist. This command is not evidence of tests until test cases have been added.
4. Add a telemetry task that snapshots measurements without holding locks across serial writes. Bound queued output and count drops under backpressure.
5. Build a serial reader with a finite timeout. Close the IDF monitor first. Save raw bytes locally for replay; keep decoded small CSVs for analysis.
6. Select compatible host packages (for example pyserial, NumPy, matplotlib and pytest if used), install into `.venv`, and record tested versions in a requirements file. Do not commit an untested dependency claim.
7. Disconnect/reconnect, reset the board, and slow the reader. The reader must resynchronize and distinguish a reboot from a continuous timeline.

## Finish when

- C and Python agree byte-for-byte on a fixed packet and checksums.
- Invalid packets never reach the plot as valid measurements.
- A slow or disconnected host does not stop control. Buffer usage stays bounded.

## Explain

Why might one serial read contain half a packet or three packets? Why is CRC different from encryption? What happens to struct layout, endianness and padding across implementations?

**Evidence:** golden packet, meaningful parser tests, replay sample and counters from a live stream.
